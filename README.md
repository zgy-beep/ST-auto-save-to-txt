## 📖 核心体验与亮点

- 🖋️ **智能问候语延迟入书**：新开聊天查看角色卡或调试预设时，**不会生成任何废弃文件**；只有当你发出第一句消息、真正开启剧情时，角色问候语才会作为**第 1 章**补写入书，从开头就完整。（前提：服务端 `/status` 上报版本 ≥ 1.7.8，且此时会话恰好只有「问候语 + 你的第一条消息」两条；半路启用插件或更早版本服务端请用【同步历史连载】补全。）
- 📚 **手机阅读器自动识别目录**：默认采用 `第 X 章 · 角色名 (原楼层: Y)` 格式，导入**微信读书、掌阅、ReadEra、多看**等主流阅读器时，**100% 自动生成可点击的树状目录**！
- 🧭 **酒馆原楼层精准溯源**：章节标题自带原始楼层标记，追溯剧情、排查漏网标签或回溯对话极其直观。
- 🔤 **原生 UTF-8 BOM 编码**：首章自动写入 UTF-8 BOM 标识与《书名》扉页，彻底杜绝老旧车载系统、老版 Windows 记事本、电子墨水屏出现“锟斤拷”乱码。
- 🔄 **智能适配“重新生成 (Regenerate)”与“划动分支 (Swipe)”**：点击酒馆重 roll 或划动分支时，只要被重写的正是**最近一次已写入的那一楼**，插件就会把小说末尾的对应章节替换为最新版本，不留废弃废案；若目标章不是文件末尾章（例如编辑过早期楼层、改过章节目录风格），服务端会**拒绝替换**并提示你用【同步历史连载】校准，绝不误删后面的章节。编辑历史楼层本身不会回改已落盘的章节。
- 👥 **多角色群聊 (Group Chat) 自动聚合**：智能识别群聊环境，将群内所有角色的回复统一编排进同一本群小说（`[群聊] 群名称 - 对话名.txt`），剧情连贯不撕裂。
- 🧹 **双重深度标签清洗引擎**：
  - **白名单（指定提取正文）**：如预设将正文写在 `<story>` 内，填入 `story` 即只提取该标签内容，自动丢弃外部所有杂乱元数据。
  - **黑名单（剔除干扰杂项）**：在正文中深度剥离 `<status>`、`<memory>`、`<ooc>`、`<variables>`、`<note>` 等信息卡。
  - **全自动思维链与草稿清理**：通用支持各类思考模型（DeepSeek、Claude 等），全自动剥离 `<think>`、`<cot>` 及各类反代无头闭合标签（如 `</think>`、`</analysis>`）。
  - **HTML 注释与表情包清洗**：过滤 `<!-- 世界书注释 -->` 与 `![图片](url)` 标记，回归纸质纯文字阅读体验。
  - **图像生成标记自动清理（v1.17.8）**：使用 bbi 等图像生成扩展时，正文里会写入 `<bbi_image>` + 英文绘图提示词（prompt）。插件会**连同提示词一起**自动清理到行末，绝不把绘图提示词当成小说正文写进书里（旧版本会残留大段英文描述）。
- 🏷️ **会话标签一键检测器（免手打）**：面板自动扫描当前对话中 AI 实际输出过的所有标签，以标签胶囊展示，点击「白」加入白名单，点击「黑」加入黑名单，悬浮还可预览标签内的实际内容。
- 👁️ **过滤效果即时预览**：修改标签名单后，点击【查看过滤效果预览】即可弹窗对比最近回复过滤前后的完整文本与字数变化，无需等到保存落盘才排查。
- 🛡️ **未安装服务端防 404 弹窗拦截**：若尚未部署服务端，扩展会自动取消勾选连载并友好提醒，绝无频繁报错烦恼。
- 📦 **纯前端免配置一键导出**：不配置服务端插件、不碰任何黑框终端，也能直接点击【📥 导出整本 TXT】，浏览器端本地排版并下载！
- 🖼️ **图片电子书（EPUB）导出**：用 bbi 等图像生成扩展给每轮回复配的插画，会**按其正文原位**嵌入 EPUB 电子书（图片来自 `extra.bbiImage`，位置来自正文 `<bbi_image>` 原位标记）；默认关闭，开启后先「图片清单预览」确认再导出，导入微信读书 / ReadEra / 掌阅即图文并茂。详见 [图片电子书（EPUB）导出](#️-图片电子书epub导出)。
- 🪄 **左下角魔法棒菜单入口**：点开聊天输入框左下角的酒馆原生 **🪄 魔法棒**，菜单里即有一项 **「小说连载阅读」**（带连载状态副标：连载中 / 已关闭），点一下直接弹出完整设置面板——不再占用「扩展程序」抽屉，入口就在手边。
- 🪟 **右下角悬浮入口（默认开启，可自由拖动）**：屏幕右下角常驻一枚**小圆钮**（34–36px，见方，几乎不挡视线），鼠标移上去或键盘聚焦时才横向展开成胶囊、显示「第 N 章」进度——**它就是一个入口，点一下即打开设置弹窗**，不再有二级面板。**按住药丸即可拖到任意位置，位置会被记住**，再也不会挡住聊天；不依赖任何具体楼层，切聊天全程跟随。不需要时在设置里关掉即可。
- 🧭 **设置弹窗标签页化（双端各一套排布）**：所有配置集中在一个弹窗里，按 **连载 / 过滤 / 排版 / 文件 / 通用** 五个标签分页——桌面端标签行在标题下方横向排列，手机端标签栏落到弹窗底部（拇指够得到）；「开启小说自动连载」总开关常驻在头部下方，任何标签下都一眼可见。**每个设置分组都是一枚独立分组条**（带底色与圆角，右侧直接显示当前值），**默认全部收起**，点标题即可展开收起——一进来就是一页清爽目录，展开哪个由你决定，而且**下次打开还记得你上次展开的是哪几块**；展开后里面的开关和路径都是「左标题 + 右控件」的扁平行，不套盒子、不层层嵌套。按 Esc / 点遮罩即可关闭，与过滤效果预览弹窗互不遮挡。
- 🔍 **过滤预览弹窗全新改版**：「入书正文 vs 原始回复」左右对照，顶部统计栏一目了然——原始字符数、入书字数、剔除字数与百分比、被剔除的标签明细（`<status>×1`、`think族×1`…）；原始回复中被剔除的内容以红色高亮标注，白名单未命中即时警告。

## ⚡ 极简上手指南（两种模式任选）

为了照顾所有阶段的用户，插件提供两种截然不同但同样好用的运作模式：

| 模式 | 适用人群 | 使用方式 | 优点 |
| :--- | :--- | :--- | :--- |
| **模式 A：纯前端免配置导出** | 小白用户 / 云酒馆使用者 / 手机 Termux / 不想碰终端的懒人 | 安装扩展后直接聊，聊完点击设置面板内 **【📥 导出整本 TXT】** | **零门槛、免配服务端、无需重启、永不报 404**，任何设备即开即用 |
| **模式 B：后台自动实时连载** | 深度阅读用户 / NAS 同步党 / 追更爱好者 | 部署服务端插件并在 `config.yaml` 开启支持，勾选「开启小说自动连载」 | **全自动无感落盘、每轮回复自动续写、重 roll 自动替换末尾** |

## 🚀 详细安装与部署教程

### 第一步：在 SillyTavern 中安装前端扩展

无论使用哪种模式，都需先安装前端扩展：

1. 打开 SillyTavern，点击顶部栏的 **扩展管理图标（积木/方块图标）**。
2. 点击 **“Install Extension”（安装扩展）**，在输入框中粘贴仓库地址：
   ```text
   https://github.com/zgy-beep/ST-auto-save-to-txt
   ```
3. 点击保存安装，完成后**刷新浏览器页面**。
4. 此时输入框左下角会出现 **🪄 魔法棒**，点开菜单即可看到 **【小说连载阅读】**；同时屏幕右下角会常驻一枚 **小说连载药丸入口**（两者都能一键打开设置弹窗）。**面板不在「扩展程序」抽屉里**——v1.13.0 起设置面板已改为独立弹窗，扩展抽屉里不会再出现「小说连载阅读」这一项。

> [!TIP]
> 如果您只需要 **模式 A（纯前端随时导出整本 TXT）**，到这里就已经全部完成了！点开 **🪄 魔法棒 → 【小说连载阅读】**（或点右下角药丸）打开设置弹窗，在【文件】标签里点击 **【📥 导出整本 TXT】** 即可。

---

### 第二步：部署服务端插件（实时自动落盘必选）

如果您希望每轮 AI 回复时，后台自动把章节悄悄写入本地文件，请执行本步以部署服务端插件：

#### 方案 1：一行命令自动部署（最简单，智能感知环境）

打开您的终端（本地电脑或服务器终端），复制对应的一行命令回车即可：

- **Windows 本机系统**（在 PowerShell 终端执行）：
  ```powershell
  irm https://cdn.jsdelivr.net/gh/zgy-beep/ST-auto-save-to-txt@main/install.ps1 | iex
  ```
- **Linux / VPS / 群晖 NAS / Docker 宿主机**（在 SSH 终端执行）：
  ```bash
  curl -fsSL https://cdn.jsdelivr.net/gh/zgy-beep/ST-auto-save-to-txt@main/install.sh | bash
  ```

> 脚本具有自适应识别能力：会自动寻找运行中的酒馆进程、定位 Docker 容器名称并自动部署进容器，完全无需手动寻址。

#### 方案 2：手动复制部署（无网络/纯离线环境）

1. 找到酒馆扩展目录中刚下载的本插件文件夹：
   - 路径通常为：`SillyTavern/public/scripts/extensions/third-party/ST-auto-save-to-txt/`（或 `data/default-user/extensions/ST-auto-save-to-txt/`）。
2. 将其中的 `plugins/auto-save` 整个文件夹，复制到 **SillyTavern 根目录的 `plugins/` 目录** 下。
3. 复制完成后，确保存在此路径：`SillyTavern/plugins/auto-save/index.js`。

#### 方案 3：启用服务端插件支持并重启酒馆

1. 打开 SillyTavern 根目录下的 **`config.yaml`** 文件。
2. 查找 `enableServerPlugins`，将其值修改为 `true`：
   ```yaml
   enableServerPlugins: true
   ```
3. **彻底重启 SillyTavern 进程**（关闭黑框终端并重新启动服务）。
4. 刷新前端网页，点开 **🪄 魔法棒 → 【小说连载阅读】**（或点右下角药丸）打开设置弹窗，勾选 **【开启小说自动连载】**，指示灯亮绿即表示连载服务已完美就绪！**面板不在「扩展程序」抽屉里**，在酒馆的「扩展」抽屉里找不到它是正常的。

### 🔁 更新说明（更新扩展后必读）

SillyTavern 的扩展更新器**只更新扩展目录**，不会同步酒馆根目录下的 `plugins/auto-save`。两者是两份独立副本，所以更新扩展后必须重新部署服务端插件，否则会出现「界面提示未检测到服务端插件」「新功能不生效」等现象。

1. 更新扩展：在酒馆「扩展」面板点更新，或按第一步重新安装本仓库。
2. **重新部署服务端插件**：重跑上文「方案 1」的一键命令，或按「方案 2」把扩展目录里的 `plugins/auto-save` 重新覆盖到 `SillyTavern/plugins/auto-save`。
3. 确认 `config.yaml` 中 `enableServerPlugins: true`，然后**彻底重启酒馆**（仅刷新网页无效）。
4. **核对版本**：设置弹窗标题右侧显示的 `vX.Y.Z` 是**扩展版本**；服务端插件版本可从 `/api/plugins/auto-save/status` 的 `version` 字段查看（需要酒馆登录态）。两者独立演进，**不要求相同**——关键是第 2 步必须做过。

## ⚙️ 连载设置手册

点开 **🪄 魔法棒 → 【小说连载阅读】**（或点右下角药丸）展开 **【📖 小说连载阅读】** 设置弹窗（**不在「扩展程序」抽屉里**）：

### 1. 章节样式与文件命名

- **开启小说自动连载**：实时连载总开关。若未部署服务端插件，系统会主动拦截并取消勾选，防止 404 弹窗。
- **连载更新时弹出轻量提示通知**：每当有新章节写入成功时，屏幕右上角弹出轻量 Toast（如 `《艾莉丝》第 12 章已自动写入`），可随时关闭。
- **显示内嵌工具条**：在最新一条 AI 回复气泡底部显示内嵌快捷操作条（展示已连载章节数、快速查看过滤效果与一键导出整本 TXT）；若追求极简无扰的气泡体验，可随时在此关闭。
- **右下角悬浮入口**：默认开启。右下角是一枚小圆钮，鼠标移上去展开后实时显示当前连载进度（如「第 12 章」），**点击即打开本设置弹窗**（所有操作都在弹窗里完成）；**按住药丸可拖到任意位置，位置自动记忆**（缩小窗口 / 横竖屏切换时会自动夹回可视区）。不需要时取消勾选即可隐藏。
- **章节目录风格**：
  - `第 X 章 · 角色名 (原楼层: Y)`（**强烈推荐**）：各大阅读器完美识别为目录，同时标明酒馆楼层，回溯查验极为方便。
  - `第 X 节 · 角色名`：纯净目录，不包含楼层信息。
  - `优雅分割线 (* * *)`：散文体，章节之间仅用星号隔开。
  - `纯净戏剧体 (【角色名】)`：剧本体，适合角色对话密集的场景。
- **文件命名规则**：
  - `角色名 - 对话名`（**推荐**）：每个新开的聊天都会生成独立的文件（如 `艾莉丝 - 2026-09-16.txt`，其中的日期来自酒馆给这次对话起的名字，插件本身不生成日期），**平行世界或新开局绝不串台、绝不相互覆盖**！
  - `仅角色名`：该角色的所有对话都会无条件追加写入到同一本小说（如 `艾莉丝.txt`）。
  - 多用户模式下会自动加账号前缀，见下方「4. 已实现的进阶行为与兼容性」。

### 2. 🏷️ 独创标签清洗引擎（白名单 / 黑名单 / 免手打检测）

玩酒馆最头疼的就是预设带有的 `<status>` 状态栏、`<think>` 思考过程、`<ooc>` 闲聊杂项。本插件提供了双重过滤机制：

```text
[原始 AI 回复]
      │
      ▼
【白名单匹配】─(未设置)────────────> [保留全部内容]
      │
      └──────(设置了标签，如 story)─> [仅提取 <story>...</story> 内部内容]
                                              │
                                              ▼
                                      【黑名单深度剔除】
                                      (剔除 status, memory, think, ooc...)
                                              │
                                              ▼
                                      [纯净优雅的小说正文]
```

- **白名单（指定正文标签）**：
  - 如果你的预设把正文包裹在固定标签里（例如 `<story>正文</story>`），在此填入 `story`。
  - **注意**：留空代表整篇全保留！若不确定预设是否有专门的正文标签，**务必留空**。
- **黑名单（排除的标签块）**：
  - 填入要剔除的标签，用半角逗号隔开，默认内置：`status,memory,details,variables,analysis,ooc,note,draft,system,log`。
  - 会把这类标签及其包含的全部子内容完整剪除。
- **会话标签检测器（免手打）**：
  - 面板会自动扫描当前聊天记录里 AI 实际吐出过的标签并列出；
  - 鼠标移动到标签上：**悬浮预览该标签内部的具体内容**；
  - 点 **「白」**：立刻加入白名单；点 **「黑」**：立刻加入黑名单；再次点击即可取消。
- **👁️ 查看过滤效果预览**：
  - 修改完名单后，点击此按钮即可弹窗查看最新一楼 AI 回复过滤前后的对比与字数差异，彻底消除过滤配置失误的后顾之忧。
  - 弹窗为「入书正文 vs 原始回复」左右对照布局：顶部统计栏显示原始字符数 → 入书字数、剔除字数与百分比、被剔除标签明细；原始回复中被剔除的内容以红色高亮标出；白名单未命中时会即时给出警告与修复建议。

### 3. 存储路径与历史同步

- **指定保存文件夹（可选）**：
  - **留空**：默认保存在 `SillyTavern/plugins/auto-save/logs/`。
  - **自定义绝对路径**：可填写本机电脑的绝对路径（如 `D:\MyNovels`）。如果填写的文件夹不存在，插件会自动创建。
  - **自定义相对路径**（如 `novels`）：以**酒馆进程的工作目录**为基准（即启动酒馆时所在的目录，通常是酒馆根目录），**不是**插件目录。
  - **边界提示**：服务端对自定义目录**不做白名单校验**——任何 Node 进程有写权限的绝对路径都会被自动 `mkdir` 并写入，请只填你自己确认安全的目录；该目录下与小说**同名**的 `.txt` 会被【同步历史连载】整文件覆盖（覆盖前服务端会先备份一份 `.bak`）。
- **📥 导出整本 TXT**：
  - 纯前端本地下载，即点即存，不受任何服务端插件配置限制。
- **【同步历史连载】**：
  - 聊到一半才想起装插件？点击此按钮，插件会一口气将当前会话之前的全部历史楼层整理排版并写入服务端文件（**整文件覆盖写**，写前自动备份 `.bak`）；后续的新回复将接着往后连载，无缝接轨。
- **试写一章**：
  - 模拟生成一节测试章节，快速校验写入是否正常。

### 4. 已实现的进阶行为与兼容性

以下行为都能在面板里找到对应控件（或由插件自动处理），列在这里是为了让「文件里为什么是这样」有据可查：

- **草稿缓冲（最新楼层延迟定稿）**：面板「排版」标签里的开关，默认**关闭**。开启后最新一楼的 AI 回复先不落盘，等你发送下一条消息时才正式定稿入书——适合一边 Roll 一边改的用户。注意：**刷新页面前尚未定稿的那一楼可能不会写入**，需要手动点【同步历史连载】补齐。
- **段落首行空两格（中文小说规范缩进）**：默认**开启**。写入 txt 时每个自然段前补一个全角缩进「　　」；关闭后按原始换行输出。
- **将你的发言作为主角对白融入小说**：默认**关闭**。开启后你自己的消息也会被编排成章节同步入书。
- **多账号文件名前缀**：酒馆以多用户模式运行时，文件名会自动带上 `[用户名] ` 前缀（如 `[alice] 艾莉丝 - 远征探索.txt`），避免不同账号的同名小说互相覆盖。
- **聊天改名自动跟随重命名**：聊天标题改名后，服务端会把已经写好的 txt 一并改名（内容整体搬迁，首行《书名》同步更新）。这套"锚点 → 文件"映射记录在服务端插件的隐藏状态文件 `plugins/auto-save/.novel-registry.json`（已被 `.gitignore` 忽略，不会上传仓库）；删掉它只会让插件忘记改名跟随关系，不影响已有 txt。
- **酒馆助手（JS-Slash-Runner）软依赖**：检测到 `window.TavernHelper` 时会额外启用楼层「已入书」徽标与改名即时刷新；**没装也能正常使用**，所有功能自动降级到酒馆原生路径，不会报错。
- **界面入口一次性迁移（`ui_v113_migrated`）**：v1.13.0 把入口从扩展抽屉搬到魔法棒菜单 + 右下角悬浮入口，老用户升级后会被自动补开一次悬浮入口；此后你自己关掉即生效，不会被再次强行打开。

## 🖼️ 图片电子书（EPUB）导出

> 适合「用 bbi 等图像生成扩展给每轮回复配了插画」的用户：把这些插画**按其正文原位**嵌入 EPUB 电子书，导入微信读书 / ReadEra / 掌阅后图文并茂地阅读。

### 前置条件

| 条件 | 说明 |
| :--- | :--- |
| **服务端插件 ≥ v1.14.0** | EPUB 打包在服务端完成（浏览器读不到本地图片文件）。老版本服务端没有 `/ebook` 接口，导出按钮会置灰并提示更新 |
| 开启「嵌入图片」 | 设置弹窗 →【文件】标签 →「图片电子书（EPUB）」分组 → 勾选。**默认关闭**，关闭时 EPUB 为纯文字，TXT 连载完全不受影响 |

### 使用步骤

1. 打开设置弹窗（🪄 魔法棒 → 小说连载阅读 / 右下角药丸）。
2. 切到【文件】标签，展开「图片电子书（EPUB）」分组：
   - 勾选 **导出时嵌入图片**；
   - 按需调整 **单图上限**（默认 5MB）、**图片总量上限**（默认 80MB）；
   - 若酒馆跑在 Docker / NAS，可填 **酒馆根目录**（如 `/home/node/app`），留空会自动推导。
3. 先点 **【图片清单预览】**（只读）：确认识别到几张图、每张图的 `slotSeq`、哪些被判定为"原位校验不一致（将退化为章尾）"、哪些缺图。**建议先看再导**。
4. 点 **【导出 EPUB 电子书】**：服务端打包后落盘到与 TXT 相同目录（`<保存目录>/<书名>.epub`），并返回嵌入/跳过/缺失统计。
5. 把 `.epub` 传到手机，用微信读书【从本地导入】/ ReadEra 打开即可。

### 图片是从哪来的、怎么定位的

- **图片来源**：每轮回复的 `message.extra.bbiImage` 结构化字段（**不是**去猜正文里的 Markdown 图片）。
- **位置来源**：正文 `mes` 里的 `<bbi_image>` 原位标记。插件把标记换成内部占位符 → 走原清洗管线 → 再还原为图片块，因此图片会落在**它原本对应的那一段**。
- **排序**：按图片的 `slotSeq` 升序（**不是**数组存储顺序——实测存储顺序可能是 `[2,1,0]`）。
- **降级**：如果某条消息的"标记数 ≠ 图片数"，该消息的图片会**统一放到章尾**并在预览里标注原因，**绝不猜测位置、也绝不丢图**。

### 图片实际在哪（路径规则）

```
消息里的 path           : /user/images/<聊天目录>/<文件名>.jpg     ← URL 前缀，不是磁盘路径
磁盘真实位置            : <酒馆根>/data/<账号>/user/images/<聊天目录>/<文件名>.jpg
Docker 容器内           : /home/node/app/data/<账号>/user/images/…
```

`/user/images/` 会按**当前登录账号**解析，所以同一 URL 在不同账号下指向不同磁盘目录。插件按 ①该聊天所属账号 ②`default-user` ③其它账号通配 的顺序查找；全部找不到才记为 `missing`（**不会静默丢弃**，会在结果与预览里列出）。

### 常见问题

- **图片没嵌进去？** 先看【图片清单预览】。若显示 0 张图，说明当前会话的消息里没有 `bbiImage` 数据（确认图像生成扩展确实给该轮配了图）。
- **导出按钮是灰的？** 服务端插件版本过旧（缺 `/ebook` 接口）。重新部署 `plugins/auto-save` 并重启酒馆。
- **某张图在 EPUB 里看不见？** 检查是否被列为 `missing`（路径找不到）或 `too_large`（超过单图上限）。部分老阅读器不支持 WebP 格式——插件不转码，建议用 PNG/JPEG。
- **双缩进？** EPUB 用 CSS `text-indent:2em` 控制段首，插件已去掉正文里的全角空格前缀，不会出现双重缩进。
- **只想要纯文字？** 不要勾选「导出时嵌入图片」，或用原来的【📥 导出整本 TXT】。

### 详细排查说明

#### 1. HTTP 404 - 未检测到服务端插件 (Not Found)
- **为什么会出现**：
  酒馆的前端扩展仅能运行在您的浏览器标签页中，而把小说文件直接写在您的电脑硬盘上，必须依靠酒馆后端的 Node.js 服务端插件。如果后端找不到 `/api/plugins/auto-save/append` 接口，就会返回 404。
- **标准解决流程**：
  1. 检查文件是否存在：进入 SillyTavern 目录，确认存在 `plugins/auto-save/index.js`。
  2. 检查主配置：打开根目录下的 `config.yaml`，确认：
     ```yaml
     enableServerPlugins: true
     ```
  3. **必须重启酒馆**：修改配置文件后，**仅刷新网页是无效的**，必须关闭运行酒馆的黑框命令行窗口，重新运行 `start.bat` 或 `node server.js`。
  4. **免服务端应急法**：如果暂时不想配置服务端，随时可以点击面板上的 **【📥 导出整本 TXT】** 纯前端一键导出，完全不依赖服务端。

#### 2. HTTP 400 - 请求参数错误 (Bad Request)
- **情形 A：云端容器与本地盘符冲突**
  - **报错提示**：`当前酒馆运行在云服务器(Linux/Docker)中，无法直接访问您本地电脑的盘符路径`
  - **原因**：很多用户使用的是群晖 NAS、云服务器或 1Panel Docker 搭建的酒馆，但在本地浏览器打开面板时，在“保存路径”习惯性填写了 `D:\小说`。Linux 容器内部根本无法理解 Windows 盘符。
  - **解决**：把该输入框清空即可使用默认目录；或在 Docker 容器映射卷中填写如 `/app/novels`。
- **情形 B：正文过滤后变为空白（面板提示“过滤后无正文可入书”）**
  - **真实行为**：**白名单未命中时引擎会整篇保留**，不会把正文清空——所以“填错白名单”不会导致 400，只会在【查看过滤效果预览】里标出「白名单未命中任何标签，已整篇保留」。
  - **真正的原因**：**黑名单配得过宽**（把正文所在的标签也列了进去），或该楼层的正文确实为空。
  - **解决**：在【查看过滤效果预览】里确认「入书正文」不为空；把黑名单里误伤的标签删掉；确定不了就把白名单/黑名单都清空重试。
  - **补充**：正文被过滤为空时前端**不会发请求**，面板只会显示“最新回复经标签过滤后无正文，已略过写入”，不会报 HTTP 400。

#### 3. HTTP 413 - 章节篇幅超出限制 (Payload Too Large)
- **原因**（两处上限都是按**过滤后文本的 UTF-8 字节数**校验的，不是按字/词数）：
  - 单章限制：`100KB` = 102400 字节 ≈ **3.4 万字**（按中文 3 字节/字；中英混排可达更多字），防止 AI 幻觉死循环持续输出无意义字符撑爆硬盘。
  - 全量同步限制：`20MB` = 20971520 字节 ≈ **700 万字**，用于防范接口恶意大包。
- **解决**：
  - 如果单章报错，在酒馆内检查最后一条消息是否异常过长；
  - 如果整本书确实极大，请直接点击 **【📥 导出整本 TXT】**，前端在浏览器直接打包生成，没有容量上限。

#### 4. HTTP 500 - 写入文件失败 (Internal Server Error)
> 界面上只会显示 `写入文件失败`（连载接口）或 `全量同步写入失败`（同步接口）；下面的 EACCES/EPERM、EBUSY、ENOSPC 等 **OS 级错误只在酒馆服务端控制台可见**，请照着控制台的原始报错判断属于哪一种。
- **权限问题 (EACCES / EPERM)**：
  - 在 Linux 或 Docker 环境下，酒馆可能是以非 root 权限（例如 `node` 账户）运行的，无法在未授权的系统目录创建或写入文件。
  - 解决方法：在服务器终端输入：
    ```bash
    chmod -R 777 /path/to/SillyTavern/plugins/auto-save
    ```
- **文件被占用 (EBUSY)**：
  - Windows 系统下，某些文本软件打开文件时会加上“写入排他锁”。关闭占用该文件的软件后重试即可。
- **磁盘已满 (ENOSPC)**：
  - 清理磁盘腾出空间后重试；空间紧张时可先用 **【📥 导出整本 TXT】** 把小说导到本地。

#### 5. 网络层异常 - Failed to fetch / 连接中断
- **原因**：浏览器根本无法与酒馆后端建立通信。
- **解决**：
  1. 检查酒馆终端是否报错崩溃；
  2. 如果是通过域名、Nginx、Cloudflare 等反向代理访问，检查反向代理规则，确保代理了 `/api/` 路径并启用了 WebSocket。

#### 6. HTTP 409 - 替换被拒绝（末尾一致性守卫）
- **为什么会出现**：
  章号是按**当前聊天记录实时重算**的，而 txt 里的章号是**历史上写下来的**。当你编辑早期楼层、删除过消息、切换过章节目录风格，或手工改过 txt，两者就会错位。旧实现遇到这种情况会把文件从目标章**一直截断到末尾**（等于静默删掉后面所有章节）；现在服务端改为**只允许替换文件里的最后一章**——目标章不是末尾章就直接拒绝，**绝不改动文件**。
- **两种 409**：
  - `未替换：第 N 章不是文件末尾章，已放弃以避免误删后续章节`（`reason: not_tail_chapter`）——出现在重 roll / 划动分支时，Toast 同义提示「第 N 章不是文件末尾章，为避免误删后续章节已放弃替换」。
  - `第 N 章已存在，已拒绝重复追加`（`reason: chapter_exists`）——追加请求的章号在文件里已存在且不是末尾章，为避免同一章写两遍而拒绝（Toast 同义提示「…（避免同一章写两遍）」）。
- **标准解决流程**：
  1. 点 **【同步历史连载】**：按当前聊天把全书重排一遍（整文件覆盖写，写前自动备份 `.bak`），让文件章号与聊天重新对齐；
  2. 再重新生成 / 划动那一楼；
  3. **不要**手工去删 txt 里的章节——那会让文件章号与聊天进一步错位，409 只会更多。
- **数据安全说明**：替换与全量同步都会先写一份同名 `.bak`（仅保留最近一份），并采用「临时文件 + rename」原子写，进程中断不会留下半截文件。

### 7. 非报错类的核心机制疑问解答 (FAQ)

#### Q1：为什么新开聊天角色发了第一句话，文件目录里却没有创建 txt？
> **答：这是为了给您带来最好的体验而特意设计的“延迟入书机制”！**  
> 很多酒馆玩家经常频繁导入角色卡、调试打招呼设定或看卡面，如果在打开聊天窗口的第一秒就无脑落盘，您的硬盘里会堆满几百个只写了一句打招呼的几百字节废弃文件。  
> 因此，插件设计为：**当您发出第一句话正式开始对话、且此时会话恰好只有「问候语 + 你的第一条消息」两条时，系统会把角色问候语作为第 1 章补写入书**（另外要求服务端 `/status` 上报的版本 ≥ 1.7.8），既不产生空卡垃圾文件，也让新书从一开始就完整。
>
> **两种补不上的情况**（都不会报错，只是没有第 1 章）：
> - 服务端插件是 1.7.8 之前的旧版本（升级后重跑一次安装命令即可）；
> - 你是在聊了几句之后才启用插件 / 才打开自动连载的——此时会话已经不止两条，请直接点 **【同步历史连载】** 把前面的楼层一次性补齐。

#### Q2：重新生成 (Regenerate) 或划动多条回复 (Swipe) 后，旧的废弃剧情会留在小说里吗？
> **答：分情况——只有“重写的是最近一次已写入的那一楼”时才会自动替换掉文件里的对应章节。**  
> 插件内置了章节末尾识别引擎：服务端会先确认要替换的那一章**确实是文件里的最后一章**，是则原位替换为最新版本；**不是则直接拒绝（HTTP 409）并原样保留文件**，面板会提示你点【同步历史连载】重新校准——绝不会为了替换而删掉后面的章节。  
> **不会自动回改的情况**：编辑较早的历史楼层、删除过消息、中途切换过章节目录风格、手工改过 txt。这些情况下文件里的旧文本会保留，请用【同步历史连载】按当前聊天重排（注意：那是整文件覆盖写）。

#### Q3：面板提示“末尾内容重复，已自动略过写入”（Toast：**“内容与前文重复，已略过”**），是不是漏存了？
> **答：完全不是，这正是防重复机制在发挥保护作用！**  
> 在网络波动、前端刷新或重复触发事件时，为防止同一个章节被反复写入导致小说里出现重复段落，服务端会自动比对文件末尾内容。如果末尾已包含相同章节，将自动跳过写入。

#### Q4：我想把我自己（主角/玩家）的互动对话也写进小说里，可以吗？
> **答：当然可以！**  
> 只需在扩展设置面板中勾选 **【将你的发言作为主角对白融入小说】** 即可。开启后，您的发言将作为对话或推进剧情的一部分同步编排入书。

#### Q5：微信读书导入后，为什么有些章节目录出不来？
> **答：建议将【章节目录风格】保持为默认的 `第 X 章 · 角色名 (原楼层: Y)`。**  
> 这种格式完全符合国内主流阅读器（微信读书、掌阅等）的正则目录识别算法；同时，插件生成的 TXT 带有 UTF-8 BOM 标识，导入后即可自动解析出目录，绝无乱码。

#### Q6：删除楼层会怎样？会不会把小说也删掉？
> **答：不会自动删章节，但会触发一次「静默全书重写」，请务必看完这段。**  
> 删除楼层后约 **1.5 秒**，插件会按**当前聊天记录**重新编排整本书，并用与【同步历史连载】相同的逻辑**整文件覆盖**目标 txt：
> - 聊天里已经不存在的那一楼，会从 txt 里消失；
> - **你手工润色过的内容、其它工具追加进这个 txt 的内容，也会一起消失**（覆盖前服务端会留一份同名 `.bak`，但只保留最近一份）；
> - 因此：**不要手工编辑正在连载的 txt**；要长期保存请先【📥 导出整本 TXT】另存副本。
>
> 这个过程在界面上只有一行状态（“连载已自动校准同步（共 N 章）”），**没有弹窗确认**，所以容易被忽略。

#### Q7：草稿缓冲（`buffer_latest_message`）是什么？
> **答：把「最新一楼」当草稿，先不落盘。**  
> 开启后每轮新回复都只是草稿，等你**发送下一条消息**时上一轮才正式定稿写入 txt——适合边 Roll 边改、不想让废案进文件的玩家。默认**关闭**。  
> 注意两点：① 最新一楼在定稿前不会出现在 txt 里，看着“少一章”是正常的；② **刷新 / 关闭页面前尚未定稿的那一楼不会写入**，刷新后可以点【同步历史连载】补齐。

#### Q8：我改了过滤设置 / 编辑了楼层，为什么小说里的章节乱了？
> **答：因为章号是按「当前聊天」实时重算的，而 txt 里的章号是历史上写下来的，两者会错位。**  
> 常见触发：改白名单/黑名单后有楼层被过滤掉（不再计入章号）、编辑或删除过楼层、切换过章节目录风格、手工改过 txt。  
> 处理办法：点一次 **【同步历史连载】**，插件会按当前聊天把全书重排一遍（整文件覆盖写，写前备份 `.bak`），章号随即对齐，此后新回复会接着正确编号。乱到一半时也可以直接用【📥 导出整本 TXT】先导出当前聊天的正确版本对比。
